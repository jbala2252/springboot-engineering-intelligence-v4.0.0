# Architecture Design

Discover current state first. Frame functional and non-functional requirements. Identify module
ownership, contracts, data flows, transaction boundaries, failure modes, deployment topology,
security boundaries, and operational constraints. Compare options across maintainability, complexity,
performance, scalability, cost, migration, and observability. Recommend the simplest design that
meets verified requirements. Include diagrams where useful, ADR, rollout/rollback, and tests.
Do not invent requirements or add speculative abstractions.
