# Test Strategy

Inspect existing test stack and conventions. Select unit, slice, integration, contract, component,
and end-to-end tests based on risk. Cover validation, boundary conditions, failures, retries,
timeouts, concurrency, serialization, transactions, and security. Avoid brittle sleeps and
over-mocking. Use Testcontainers only if already approved/available and compatible. Run the
smallest relevant suite first and report unexecuted tests honestly.
